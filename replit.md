# SMC Trading Bot

## Overview

A Telegram-based cryptocurrency trading bot that uses Smart Money Concepts (SMC) for market analysis. The bot provides automated trading signals and execution on the Solana blockchain through Jupiter DEX integration. Users interact exclusively through Telegram - the web frontend simply redirects users to the bot.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture
- **Framework**: React 18 with TypeScript, built with Vite
- **Routing**: Wouter (lightweight alternative to React Router)
- **State Management**: TanStack React Query for server state
- **UI Components**: shadcn/ui built on Radix UI primitives
- **Styling**: Tailwind CSS with CSS variables for theming

The frontend is minimal since all trading functionality lives in the Telegram bot. It primarily serves as a landing page directing users to Telegram.

### Backend Architecture
- **Runtime**: Node.js with Express (TypeScript, ESM modules)
- **Entry Point**: `server/index.ts`

Key modules:
- `server/telegram.ts` - Telegram bot using node-telegram-bot-api, handles all user commands and interactions
- `server/signals-worker.ts` - Automated signal generation using AI analysis of monitored crypto pairs
- `server/solana.ts` - Jupiter DEX integration with multi-endpoint fallback for reliable swap execution
- `server/storage.ts` - Database abstraction layer with AES-256-CBC encryption for wallet private keys
- `server/ai.ts` - OpenAI/OpenRouter integration for chart analysis and market insights
- `server/price-service.ts` - Multi-source price fetching (Binance, CryptoCompare fallback)

### Data Storage
- **Primary Database**: SQLite (`local.db`) using libsql client
- **ORM**: Drizzle ORM with SQLite dialect
- **Schema**: `shared/schema.ts`
- **Backup**: Supabase integration available but currently disabled (local-only mode)

Database tables:
- `users` - Telegram user profiles, trading preferences (safety profile, fee tiers, MEV protection)
- `wallets` - Encrypted Solana wallet storage (AES-256-CBC encryption)
- `signals` - Trading signals generated by the AI system
- `trades` - Trade execution history
- `user_lanes` - User-specific signal lane configurations (high/med/low priority)
- `group_bindings` - Telegram group/topic bindings for signal distribution
- `user_subscriptions` - Subscription management

### Security Architecture
- Wallet private keys encrypted using AES-256-CBC with SESSION_SECRET as master key
- Encryption/decryption handled in `server/storage.ts`
- MEV protection available for Solana transactions

## External Dependencies

### APIs and Services
- **Telegram Bot API** - Primary user interface via node-telegram-bot-api
- **OpenRouter/OpenAI** - AI-powered market analysis and chart extraction (configurable via OPENROUTER_API_KEY or OPENAI_API_KEY)
- **Jupiter DEX** - Solana token swaps with multiple fallback endpoints for reliability
- **Solana RPC** - Blockchain interaction (configurable via SOLANA_RPC_URL, defaults to mainnet-beta)
- **Binance API** - Primary price data source
- **CryptoCompare** - Fallback price data source
- **Supabase** - Optional PostgreSQL backup (currently disabled)

### Required Environment Variables
- `TELEGRAM_BOT_TOKEN` - Telegram bot authentication
- `SESSION_SECRET` - Master key for wallet encryption (critical for security)
- `OPENROUTER_API_KEY` or `OPENAI_API_KEY` - AI service authentication
- `SOLANA_RPC_URL` - Optional, defaults to public endpoint

### Optional Environment Variables
- `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` - For cloud backup functionality
- `OPENROUTER_BASE_URL` - Custom AI endpoint
